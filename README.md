# Discount Engine

Движок расчёта скидок для маркетплейса. Спроектирован по паттернам Стратегия, Фабрика, Синглтон. Движок работает только с абстракцией скидки и не знает конкретных классов.

## Установка

```
pip install -r requirements.txt
```

## Запуск демо

```
python demo.py
```

## Запуск тестов

```
pytest tests/ -v
```

## Схема классов

- **Discount** (ABC) — контракт: имя + метод `apply(ctx)`, возвращает `AppliedDiscount` или `None`.
- **PercentDiscount** — процент от текущей суммы товаров.
- **FixedDiscount** — фиксированная сумма при пороге.
- **ThreeForTwoDiscount** — 3 по цене 2 в категории.
- **PromoCodeDiscount** — промокод (процентный или фиксированный), одноразовый в рамках заказа.
- **LoyaltyDiscount** — 5% при последней покупке ≤ 30 дней назад.
- **FreeDeliveryDiscount** — бесплатная доставка при сумме строго выше порога.
- **FirstOrderDiscount** — 10% при первом заказе.
- **DiscountFactory** — создаёт стратегию по словарю-конфигу.
- **PricingEngine** — применяет стратегии по стадиям.
- **DiscountContext** — единственный изменяемый объект одного расчёта: текущая сумма товаров, доставка, breakdown, использованные промокоды.
- **DiscountRegistry** (Singleton) — реестр создателей, готов к расширению.
- **ConfigProvider** (Singleton) — хранит список конфигов скидок.

## Порядок применения скидок

1. **3 по цене 2** — по всем товарам заданных категорий.
2. **Процентные** — включая победителя конфликта «обычная процентная vs процентный промокод».
3. **Фиксированные** — включая фиксированные промокоды.
4. **Бесплатная доставка** — проверяется по итоговой сумме товаров.

Внутри одной стадии скидки применяются в порядке из конфигурации. Каждая следующая считается от уже уменьшенной суммы.

## Конфликт процентной скидки и процентного промокода

Если в конфигурации есть и обычная процентная скидка, и процентный промокод, движок **до применения** считает выгоду каждого на одной и той же текущей сумме товаров (после стадии «3 по цене 2»). Побеждает больший. **При равенстве побеждает промокод.** Проигравший в этом конфликте участник не применяется.

Лояльность и скидка первого заказа считаются отдельными процентными скидками и **не участвуют в конфликте** — они применяются в общем порядке стадии процентных скидок вместе с победителем пары.

## Округление

Используется банковское округление (**round half to even**) до копеек:

```python
Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_EVEN)
```

Округляется **каждый** промежуточный денежный результат — сумма после применения каждой скидки. Это зафиксировано и используется одинаково во всех расчётах.

Пример: `0.005` округляется до `0.00` (half to even), а не до `0.01`.

## Промокоды

- Сравнение кодов: **точное, регистрозависимое**. Промокод `SALE10` не совпадает с `sale10`.
- Срок действия **включителен**: код работает и в дату `expires`.
- Одноразовость в рамках одного заказа: один и тот же код не применяется повторно в одном расчёте.
- Неизвестный (нет в `order.promoCodes`) или просроченный код не применяется.

## Лояльность

Граница **30 дней включительна**: покупка ровно 30 дней назад подходит. Будущая дата в `lastPurchaseDate` считается некорректной — скидка не применяется.

## Бесплатная доставка

Порог срабатывает **строго больше** N (не «больше или равно»). Скидка равна стоимости доставки на момент применения. Если доставка уже 0 — запись в breakdown не добавляется.

## Некорректный ввод

- `quantity <= 0` — выбрасывается `ValueError` в конструкторе `CartItem`.
- Неизвестный тип скидки в конфиге — `ValueError` в `DiscountFactory`.
- Отрицательные деньги и другие некорректные значения не проверяются специально: предполагается, что входные данные валидны по контракту задания.

## Расширение

Чтобы добавить новую скидку:

1. Создать класс-наследник `Discount`, реализовать `apply` и объявить `stage`.
2. Добавить ветку в `DiscountFactory.create`.
3. Зарегистрировать тип в `DiscountRegistry` (если используется).

`PricingEngine` и модели при этом не меняются.
